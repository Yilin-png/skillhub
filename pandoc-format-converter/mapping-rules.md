## 1. 标题层级对照表

### 1.1 中文编号识别正则

```
章节类：
  /^第[一二三四五六七八九十百千万零〇\d]+[章部篇]\s*/
  /^第[一二三四五六七八九十百千万零〇\d]+[节段]\s*/

汉字编号：
  /^[一二三四五六七八九十]+[、．.]\s*/
  /^[（(][一二三四五六七八九十]+[）)]\s*/
  /^[壹贰叁肆伍陆柒捌玖拾]+[、．.]\s*/

阿拉伯数字编号：
  /^\d+[、．.]\s*/
  /^[（(]\d+[）)]\s*/
  /^[①②③④⑤⑥⑦⑧⑨⑩]+\s*/

字母编号：
  /^[a-zA-Z][)）、．.]\s*/
```

### 1.2 层级分配策略

按文档中实际出现的编号体系自顶向下分配 H1-H6，保持连续不跳级。超过 H4 的通常转为列表。常见模式：

模式 A（公文体）：第X章→H1、第X节→H2、一/二→H3、(一)(二)→H4、1./2.→列表

模式 B（论文体）：一/二→H1、(一)(二)→H2、1./2.→H3、(1)(2)→列表

模式 C（简单文档）：一/二→H1、1./2.→H2

### 1.3 强制规则

**规则 A — 标题必须从 H1 开始**：正文最高层级编号映射为 `#`（H1）。YAML front matter 的 `title:` 是文档元数据，不占用正文标题层级。禁止全文标题从 `##` 起步。

**规则 B — 转换后去除原始编号**：中文编号在转为 Markdown 标题后必须删除。`#` 的层级本身表达结构，保留编号是冗余。

正确示例：
```
一、研究背景       → # 研究背景
（一）数据来源     → ## 数据来源
第二章 文献综述    → # 文献综述
1. 样本选取        → ### 样本选取
```

错误示例：
```
一、研究背景       → # 一、研究背景      ← 冗余编号
（一）数据来源     → ## （一）数据来源    ← 冗余编号
```

例外：编号是标题语义的一部分时保留（如「第一次世界大战」「三体问题」）。

## 2. 标题 vs 列表 vs 定义列表判定

遇到编号或结构化文本时，三选一判定：

**判定为标题**：后跟多段正文（≥100字）；后面存在更低层级子编号；内容是名词性短语；该模式在全文中一致用作结构分隔。

**判定为列表项**：多个连续编号项每项≤1行；以 `；` 结尾；前有引导语（如"包括以下几点："）；数量≥5且每项较短。

**判定为定义列表**（新增）：多个并列段落各以粗体/高亮短语开头后跟解释；使用"术语——解释"或"术语：解释"结构；连续多段相同"关键词+分隔符+长段解释"模式。详见第 3 节。

## 3. 定义列表识别与转换

### 3.1 四种中文定义列表模式

**模式 A — 冒号分隔**：
```
输入：  术语A：解释内容
        术语B：解释内容
输出：
术语A
:   解释内容

术语B
:   解释内容
```

**模式 B — 破折号分隔**：
```
输入：  表格——基础语法根本没有表格支持。扩展语法用管道符...
        脚注与引用——学术写作离不开脚注和文献引用...
输出：
表格
:   基础语法根本没有表格支持。扩展语法用管道符...

脚注与引用
:   学术写作离不开脚注和文献引用...
```

**模式 C — 粗体术语+解释段落**：
```
输入：  **表格**——基础语法根本没有表格支持。
        **脚注与引用**——学术写作离不开脚注。
输出：
表格
:   基础语法根本没有表格支持。

脚注与引用
:   学术写作离不开脚注。
```

**模式 D — 独立术语行+缩进释义**：
```
输入：  术语A
            这是对术语A的解释...
        术语B
            这是对术语B的解释...
输出：
术语A
:   这是对术语A的解释...

术语B
:   这是对术语B的解释...
```

### 3.2 语法要求

- 术语行与 `:   ` 之间**不加空行**
- `:` 后跟 3 个空格（即 `:   `）
- 不同定义对之间**加空行**
- 需确保 pandoc 使用 `+definition_lists` 扩展（默认已启用）
- 映射到 Word 的 Definition Term（粗体）和 Definition（缩进）样式

## 4. 正文与段落规则

- **去除首行缩进**：删除全角空格 `\u3000` 和行首半角空格
- **段落分隔**：Markdown 段落之间必须有空行
- **引用块**：`【按语】`、`编者注`、`编者按` 等关键词 → `> 引用文本`
- **行块**（保留换行位置，诗歌/地址）：每行以 `| ` 开头
- **中文全角标点**（必须遵守）：
  - 引号使用「」『』或""''，**不使用半角 `""` `''`**
  - 括号：中文语境用（），英文/代码语境用 `()`
  - 冒号分号等：中文语境用全角 `：；？！`
  - 逗号句号：使用 `，` `。`
  - 原则：中文句子用全角标点，英文/代码片段用半角标点，各自归属

## 5. 列表转换规则

- 无序：`• · - ※ ★` → `- ` ，嵌套用 2~4 空格缩进
- 有序：`1、 ① 1.` → `1. `
- 任务列表：`□未完成` → `- [ ] 未完成` ，`☑已完成` / `√已完成` → `- [x] 已完成`
- 紧凑列表（项之间无空行）→ Compact 样式
- 宽松列表（项之间有空行）→ Body Text 样式

## 6. Pandoc 扩展语法映射

### 6.1 脚注

```
行内脚注（默认）：  文本^[脚注内容]。
标准脚注（仅多处引用同一条时）：  文本[^1]。    [^1]: 脚注内容。
```

**一律使用行内脚注 `^[内容]`**，仅当同一条脚注在多处被引用时才使用标准脚注 `[^id]`。

中文文档中 `①②③` 标注的注释应直接在正文对应位置转为 `^[脚注内容]`。

### 6.2 文献引用

```
正文中：  根据张三的研究[@zhang2024]，该方法...
          多文献引用[@zhang2024; @li2023]
参考文献：pandoc --citeproc --bibliography refs.bib input.md -o output.docx
```

输出映射到 Bibliography 样式（悬挂缩进）。

### 6.3 数学公式

```
行内公式：  质能方程 $E=mc^2$ 是物理学基础。
独立公式：
$$
\int_0^{\infty} e^{-x^2} dx = \frac{\sqrt{\pi}}{2}
$$
```

Pandoc 自动将 LaTeX 数学转为 Word 原生 OMML 公式对象，不需要额外样式。中文文档中如遇 `E=mc²` 等 Unicode 上标写法，应转为 LaTeX 语法 `$E=mc^2$`。

### 6.4 上标与下标

```
上标：  E=mc^2^ 或 2^10^ = 1024
下标：  H~2~O
```

需 `+superscript +subscript` 扩展（默认启用）。中文文档中 `²` `₂` 等 Unicode 上下标字符应转为 Pandoc 语法。

### 6.5 标题标识符与交叉引用

```
定义标识符：  ## 研究方法 {#sec-method}
引用：        详见[第二节](#sec-method)。
```

输出为 Word 内部超链接（Hyperlink 样式 + 书签）。中文文档中"见上文""见第X章"等表述应识别并转为交叉引用。

### 6.6 代码块增强

```
基本：     ```python
           print("hello")
           ```

带属性：   ```{.python .numberLines startFrom="5" caption="示例代码"}
           print("hello")
           ```
```

语法高亮和行号由 pandoc 处理。代码块映射到 Source Code 段落样式，内部字符用 Verbatim Char。

### 6.7 行块（Line Blocks）

```
| 窗前明月光，
| 疑是地上霜。
| 举头望明月，
| 低头思故乡。
```

每行以 `| ` 开头，保留精确的换行位置。用于诗歌、地址、歌词等不应被重排的文本。

### 6.8 小型大写与自定义样式

```
行内自定义：  [文字]{.smallcaps}
              [特殊格式]{custom-style="字符样式名"}

段落自定义：  ::: {custom-style="段落样式名"}
              这段文字使用 reference.docx 中的自定义样式。
              :::
```

## 7. 表格转换规则

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|-------:|
| 文本   | 文本 |   文本 |

: 表 1 实验数据汇总
```

- 表格标题用 `: 标题文本` → Table Caption 样式
- 表格样式由 reference.docx 的 Table / Normal Table 控制
- Pandoc 还支持多行表格（grid table）和管道表格（pipe table）

## 8. 行内格式规则

| 场景 | 输出 | Word 效果 |
|---|---|---|
| 原文加粗 | `**文字**` | Bold |
| 原文着重号/下划线 | `*文字*` | Italic |
| 技术术语/代码 | `` `代码` `` | Verbatim Char |
| 删除线 | `~~文字~~` | Strikeout |
| 超链接 | `[文字](URL)` | Hyperlink |
| 上标 | `^文字^` | Superscript |
| 下标 | `~文字~` | Subscript |

书名号 `《》` 保留原样，不额外加格式。

## 9. 元数据 YAML 规则

```yaml
---
title: "文档标题"
subtitle: "副标题"

date: "2025年1月1日"
abstract: |
  摘要内容。

## 10. Pandoc → Word 样式完整对照

### 段落样式

| Markdown 元素 | Word 样式名 | 关键要求 |
|---|---|---|
| `#` ~ `######` | heading 1 ~ 6 | outlineLvl + 黑体 + 全部加粗 |
| 普通段落 | Body Text | **不是 Normal** |
| 标题后首段 | First Paragraph | **须 firstLine=0** |
| `> 引用` | Block Text | 无斜体 |
| 紧凑列表 | Compact | firstLine=0 |
| 定义术语 | Definition Term | 粗体 + **须 firstLine=0** |
| 定义内容 | Definition | 缩进 + **须 firstLine=0** |
| 代码块 | Source Code | 动态生成，basedOn Body Text |
| YAML 元数据 | Title/Subtitle/Author/Date/Abstract | Date 不用中文名 |
| 参考文献 | Bibliography | 悬挂缩进 |
| 图表说明 | Image/Table Caption | 无斜体，basedOn caption |
| 图片容器 | Figure / Figure With Caption | 名称不是 Captioned Figure |
| 脚注 | footnote text | — |
| 目录标题 | TOC Heading | 名称不用中文 |

### 自定义段落样式

| Markdown 语法 | Word 样式名 | 关键要求 |
|---|---|---|
| `::: {custom-style="Quote-Block"}` | Quote-Block | basedOn Body Text，左缩进 1cm，11pt |
| `::: {custom-style="Signature-Block"}` | Signature-Block | basedOn Body Text，右对齐 |

### 字符样式

| 元素 | 样式名 | 关键要求 |
|---|---|---|
| 行内代码 | Verbatim Char | **须 basedOn BodyTextChar** |
| 超链接/交叉引用 | Hyperlink | — |
| 脚注标记 | footnote reference | 上标 |
| 正文字符 | Body Text Char | link 到 Body Text |
| 基础字符 | Default Paragraph Font | — |

### 自定义字符样式

| Markdown 语法 | 样式名 | 关键要求 |
|---|---|---|
| `[文字]{custom-style="Emphasis-Strong"}` | Emphasis-Strong | 加粗 + 暗红色 #C00000 |
| `[文字]{custom-style="Term"}` | Term | 下划线 |
| `[文字]{custom-style="Foreign"}` | Foreign | 斜体 |
| `[文字]{custom-style="Redline"}` | Redline | 红色 #FF0000 + 下划线 |

## 11. reference.docx 质量检查清单

基于实际修复经验，以下问题最常见：

| 优先级 | 检查项 | 后果 |
|---|---|---|
| 必须 | First Paragraph 取消首行缩进 | 否则标题后首段也会缩进，不符合排版惯例 |
| 必须 | Definition 取消首行缩进 | 否则定义内容双重缩进 |
| 必须 | VerbatimChar basedOn BodyTextChar | 否则代码不继承正文基础属性 |
| 必须 | 样式名全部英文 | 否则 pandoc 无法匹配 |
| 强烈 | Heading 1~6 指定黑体 | 否则继承正文字体 |
| 强烈 | Heading 5~6 加粗 | 否则视觉层级断裂 |
| 强烈 | Block Text / Caption 去斜体 | 中文斜体可读性差 |
| 建议 | Table basedOn Normal Table | 继承链完整 |
| 建议 | SourceCode basedOn Body Text | 继承链一致 |
| 建议 | 6 个自定义样式全部存在 | 否则 custom-style 语法静默失效 |
| 建议 | Redline 红色+下划线 | 否则修订标注不醒目 |

## 12. 边界案例与常见陷阱

### 12.1 Body Text 不是 Normal

修改 Normal 不直接改变正文。必须修改 Body Text。

### 12.2 定义列表的歧义

"术语——解释"格式可能与普通破折号用法混淆。判定条件：连续多段使用相同结构，且术语部分是简短名词。单独一段中出现破折号不构成定义列表。

### 12.3 数学公式中的中文

LaTeX 数学环境中不能直接放中文。如需在公式中使用中文文字：`$\text{速度} = \frac{\text{距离}}{\text{时间}}$`。

### 12.4 文献引用的前置条件

`[@citekey]` 语法要求：准备 `.bib` 文件 → YAML 中声明 `bibliography: refs.bib` → 编译命令加 `--citeproc`。缺少任一条件，引用标记将作为普通文本输出。

### 12.5 Source Code 动态生成

pandoc 不从 reference.docx 读取 Source Code 样式。要改代码字体，修改 Verbatim Char。

### 12.6 交叉引用的限制

Pandoc 原生交叉引用只支持链接到标题标识符。要实现图表编号交叉引用（如"见图 3"），需要 pandoc-crossref 过滤器。

### 12.7 行内脚注 vs 标准脚注

**默认使用行内脚注 `^[内容]`**。行内脚注更紧凑，语义就近，是本文档的首选格式。标准脚注 `[^id]` 仅在以下情况使用：同一条脚注需要在多处被引用。pandoc 输出到 Word 时两者效果相同。

### 12.8 任务列表的兼容性

`- [ ]` / `- [x]` 输出到 Word 时转为 Unicode 字符（☐/☒），不是 Word 原生复选框控件。如需交互式复选框，需要后期在 Word 中手动替换。

### 12.9 Quote-Block vs Block Text

`> 引用` 映射到 pandoc 内置的 Block Text 样式；`::: {custom-style="Quote-Block"}` 映射到自定义的 Quote-Block 样式。前者用于短引用、按语；后者用于长段法条、合同条款等需要更精细排版控制的场景。两者不可混用。

### 12.10 Redline 不是修订模式

Redline 是纯视觉标记（红字下划线），不触发 Word 的 Track Changes 功能。设计用于谈判场景：手动标记己方新增条款，让对方一眼看到，无需开启修订模式。

## 13. 自定义样式识别与转换

reference.docx 中包含 6 个自定义样式，通过 Pandoc 的 `custom-style` 属性调用。

### 13.1 段落级自定义样式

语法：`::: {custom-style="样式名"}` + 内容 + `:::`

**Quote-Block（引文块）**：
```
识别：长段引用他方文件、法律法规条文、合同原文、判决书引文
关键词："根据《...》第X条规定"、"原文如下"、"合同约定"

输入：  根据《民法典》第五百零九条规定：
        当事人应当按照约定全面履行自己的义务。

输出：
::: {custom-style="Quote-Block"}
当事人应当按照约定全面履行自己的义务。
:::
```

**Signature-Block（落款）**：
```
识别：文档末尾的署名、日期、单位名称、盖章位置
关键词："此致"、"敬礼"、右对齐的人名/单位/日期

输出：
::: {custom-style="Signature-Block"}
北京市XX律师事务所

二〇二五年一月一日
:::
```

### 13.2 字符级自定义样式

语法：`[文字]{custom-style="样式名"}`

**Emphasis-Strong（重点强调）**：
```
识别：需要视觉跳出的关键词，比普通加粗更强烈
场景：合同核心条款关键词、风险等级、结论性判断

输出：  本交易构成[重大资产重组]{custom-style="Emphasis-Strong"}。
```

**Term（术语）**：
```
识别：首次出现的专有名词、法律术语、缩写定义
场景："以下简称"、首次出现的公司简称、法律概念

输出：  [北京XX科技有限公司]{custom-style="Term"}（以下简称「目标公司」）...
```

**Foreign（外文）**：
```
识别：中文语境中出现的拉丁文、英文术语
场景：法律拉丁语（如 bona fide）、英文专业术语

输出：  该交易应遵循[bona fide]{custom-style="Foreign"}原则。
```

**Redline（修订标注）**：
```
识别：谈判/起草中手动标记的新增内容
场景：合同修改稿中己方新增的条款、修改的措辞
用途：不开启 Word 修订模式，仅用视觉标记（红字下划线）

输出：  乙方应在[收到通知后十五个工作日]{custom-style="Redline"}内完成交割。
```

### 13.3 判定优先级

当内容可能适用多个样式时，按以下优先级判定：

1. **Redline** — 如果用户明确标记为新增/修改内容，优先使用
2. **Quote-Block vs Block Text** — 长段引用（≥2句）用 Quote-Block；短引用/按语用 `>`（Block Text）
3. **Term vs Foreign** — 中文专有名词用 Term；外文词用 Foreign
4. **Emphasis-Strong vs bold** — 需要颜色+粗体视觉跳出时用 Emphasis-Strong；普通强调用 `**bold**`
