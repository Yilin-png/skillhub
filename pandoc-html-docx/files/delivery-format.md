# M&T 对外备忘录版式（对照终稿）

以已发出的问题梳理类 Word 为默认观感（例：`汉桥资本 - 新设基金备案问题梳理 - M&T - 20260807.docx`）。本 skill 生成稿应贴近下列约定；与 `layout.md` 冲突时，**交付观感以本文件为准**，分页/居中机制仍由 `build.py` + `docx_layout` 保证。

## 封面元数据

| 字段 | 习惯写法 |
|------|----------|
| `title` | 事项名（可含客户简称 + 主题），如「汉桥资本新设基金备案问题梳理」 |
| `subtitle` | 出具主体，如「北京植德（深圳）律师事务所」 |
| `author` | 文稿状态，如「初稿」 |
| `date` | `2026年8月7日`（中文日期） |
| `abstract` | 可选；无实质内容可不写 |

页眉植德/M&T 标识、页脚页码由 `reference.docx` 提供；勿在 MD 里手写页眉页脚。

## 正文结构

1. 标题从 `#` 起（H1），**去掉**「一、」「1.」等编号前缀（Word 目录/样式可再显编号）。  
2. 章下先写叙述，再接表；**不要**为每张表加「结构化对照如下：」。  
3. 问题清单类文档：首章「问题总览」用扁平总表即可；分章再展开要点表。  
4. 分章标题宜短（如「注册资本」「专职员工」），避免过长章节名。

## 表格观感（必须）

| 项 | 要求 |
|----|------|
| 表头文字 | **水平居中**（`build.py` 后处理强制；HTML/`print.css` 亦声明 center） |
| 表头底色 | **统一灰 `#D9D9D9`**（月刊三类与 `mt-plain` 相同；不再用粉/红） |
| 表格宽度 | **通栏**（与版心等宽；`table_fit` 强制；勿写像素宽） |
| 列宽与内边距 | **按内容自适应**：序号列收窄居中；主要文句列加宽并增加单元格边距 |
| 表头行 | 使用 `<thead><th>…</th></thead>` |
| 表前套话 | **禁止**「结构化对照如下：」等批量模板句 |
| 合并 | 仅 `colspan` / `rowspan`；分类列可用 `<th rowspan>` |
| 序号列 | 表头写「序号」即可自动收窄居中；亦可在单元格加 `class="num"` |

验收：

```bash
python scripts/inspect_docx.py out.docx
# 期望：每张有表头的表显示「灰底✓ 居中✓」
```

## 表头颜色与宽度

月刊三类表（`mt-reg` / `mt-discipline` / `mt-penalty`）与对外备忘录 `mt-plain` **同一套表样式**：灰表头、通栏。class 只标栏目语义，**不要**再为月刊单独上粉底或分套列宽。**无论哪类，表头文字均须居中。**
