# 局部文本 → HTML 结构化表（半自动 · 合并优先）

适用于 `pandoc-html-docx`：把某段叙述收成 **带 `colspan` / `rowspan` 的 HTML 表**，用合并单元格表达层级与对照；**不是**全文自动制表。

与 `pandoc-word-convert/files/text-to-table.md` **共用**半自动策略与「原文保留」；本文件增量是：**何时、如何用合并把结构做深**。

---

## 策略：半自动（同 word-convert）

| 阶段 | 行为 |
|------|------|
| 识别 | 结构明显（尤其有**分组 / 对照 / 文号块 / 主从字段**）时主动提议 |
| 预览 | 须给出：**列结构 + 合并示意**（哪格 rowspan/colspan）+ 1–2 行样例 |
| 确认 | **用户确认后再写入**；用户已说「做成表 / 用合并表」可直接写 |
| 不落盘 | 无稳定字段、硬凑合并无语义增益 → 不提议或只问一句 |

---

## 强制：原文保留（宁可重复）

1. 据以制表的原文**完整保留**，不得为去重删句。  
2. HTML 表接在原文**之后**，作附加结构化视图。  
3. 禁止用表替换原文或改成「详见下表」抽空正文。  
4. **表前默认不加过渡套话。** 禁止每段/每节重复写「结构化对照如下：」「要点汇总如下：」「如下表所示：」等空衔接句；叙述写完后**直接接** `<table>`。  
5. 仅当叙述本身需要引导语时可用一句有实质信息的话（如「主要内容如下：」「协会反馈口径如下：」），不得为制表而批量插入模板句。

```text
[导语/标题]
[原文……]          ← 完整保留
[<table>……]       ← 直接接表；勿插「结构化对照如下：」
```

## 何时走本 skill（相对 pipe-table）

| 信号 | 优先结构 | 合并用法 |
|------|----------|----------|
| 同一大类下多细项 | 分类列跨行 | `rowspan` 挂在分类/`th` |
| 表头或「要求」跨多子列 | 表头跨列 | `thead` 里 `colspan` |
| 处分决定书 / 案号 / 章节横幅 | 全宽标题行 | `tr.banner` + `td colspan=N` |
| 检方 vs 辩方、一审 vs 二审 | 对照表；争点可跨行 | 争点列 `rowspan`，两侧分列 |
| 金额总—分、罪名—笔数 | 树状表 | 父行 `colspan` 作小计/合计数，子行展开 |
| 仅扁平二维、无层级 | **改回** word-convert pipe-table | 不必为合并而合并 |

**原则**：合并必须对应真实语义层级；禁止空单元格假装合并。

## 提议时必须展示的「合并草图」

向用户提议时，除列名外至少用一种方式标明合并，例如：

```text
| 争点（rowspan↓） | 检方/一审 | 辩方/二审 |
| 款项性质         | ……        | ……        |
| 樊澄角色         | ……        | ……        |
```

或直接给出精简 HTML 骨架（可省略长文）：

```html
<table class="mt-plain">
  <thead>
    <tr><th>大类</th><th>细项</th><th>内容</th></tr>
  </thead>
  <tbody>
    <tr>
      <th rowspan="2">利用影响力</th>
      <td>2014-03</td><td>100万元……</td>
    </tr>
    <tr>
      <td>2017-03</td><td>240万余元……</td>
    </tr>
  </tbody>
</table>
```

## 常用结构模式（制表时优先套用）

### A. 分类—细项（rowspan）

适用：履历阶段、罪名下多笔、条款下多点。

```html
<table class="mt-reg">
  <thead>
    <tr><th>分类</th><th>细项</th><th>内容</th></tr>
  </thead>
  <tbody>
    <tr>
      <th rowspan="2">共同受贿</th>
      <td>金额</td><td>3000万元</td>
    </tr>
    <tr>
      <td>共同人</td><td>胞弟樊群</td>
    </tr>
  </tbody>
</table>
```

### B. 表头跨列（colspan）

适用：「事项 | 具体要求（含多列）」类新规表。

```html
<thead>
  <tr><th>事项</th><th colspan="2">具体要求</th></tr>
</thead>
```

### C. 横幅行（全宽）

适用：文号、案名、章节标题压在表体之上。

```html
<tr class="banner">
  <td colspan="3">一审认定 · 利用影响力受贿410万余元</td>
</tr>
```

### D. 对照表 + 争点跨行

适用：诉辩对立、多轮程序对同一争点的不同表述。

```html
<tr>
  <th rowspan="2">3000万元性质</th>
  <td>检方</td><td>共同受贿对价</td>
</tr>
<tr>
  <td>辩方</td><td>套取工程款之贪污赃款</td>
</tr>
```

### E. 合计行跨列

适用：分项列举后给总额。

```html
<tr>
  <th colspan="2">一审认定合计</th>
  <td>3847万余元</td>
</tr>
```

Class 选用：`mt-reg` / `mt-discipline` / `mt-penalty` / `mt-plain`（见 `html-tables.md`）。

## 与 word-convert 的衔接

| 情况 | 做法 |
|------|------|
| 用户已在 word-convert 得到 pipe-table，后又要合并 | 将该表改写为 HTML 合并表（前后空行），**原文与表后视图仍保留**，整篇改走 `build.py` |
| 一开始就看出需要层级/对照/横幅 | 直接在本 skill 半自动提议 HTML 表，勿先做扁平表再拆 |
| 扁平表足够 | 留在 word-convert，不必强行 html-docx |

## Agent 操作清单

```text
- [ ] 圈定原文范围
- [ ] 判断：扁平够用 → 指向 word-convert；需要层级/对照/横幅 → 本 skill
- [ ] 提议：列 + 合并草图 +「原文保留、表可重复」
- [ ] 用户确认（或已有明确指令）
- [ ] 写入 MD：原文 + 其后直接 HTML <table>（无「结构化对照如下：」套话）
- [ ] build.py 出 docx；看校验摘要（colspan/rowspan 数与 lint 一致、灰底✓ 居中✓、通栏）；目视版式
```
